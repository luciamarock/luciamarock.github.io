SmartControllers.controllersInterface.create_validators()[source]

Recipes (from file .json) loaders

errors a list of error messages

At the beginning this function tries to create the validator objects (utilities.validation.validation_engine.create), if the creation is successfull it register the object in the module level validators dictionary (in case to be reused by other modules). The validators are declared in the settings.ini file.

call the validate method like this:

errors = validators[validator_name].validate(registered_instances[instance],PVs,os.path.splitext(filename)[0])

SmartControllers.controllersInterface.parse_xml_instances()[source]

Called right after parse_xml_types function by the main_program.

This function mirrors parse_xml_types but parses the .xml configuration files for the Controller’s instances. Unlikely the parse_xml_types, this function “walks” also the sub-directories of the UF.settings[“controller_instances_location”]. This allows the users to create their own organization structure in the file-system.

When parsing the xml files, if the instance name is not found in the module-level registered_instances dictionary, this function proceed to the call of SmartControllers.factories.instances_factories.create_instance creation function for the Instances.

Later on, if the returned instance is not None, it register the object in the registered_instance dictionary and

it calls the project model class to add the new created object among the ProjectModel nodes.

SmartControllers.controllersInterface.parse_xml_types()[source]

It gets called immediately from the main_program

This function is responsible for collecting the .xml files describing the Controller’s types.

It goes into the directory specified in UF.settings[“controller_types_location”] and collects all the .xml files in the root folder, please notice it does not walk the sub-folders !

For each type .xml file it retrieves the root node and with that, it invokes the SmartControllers.factories.types_factories.create_type function in order to create a class object representing the current type of Smart Controller.

Once the software object is created it register it in the module level registered_types dictionary.

At the beginning this function also initializes the log (writing all the settings) and instantiates the projectmodel.projectModel.projectmodel software object (Project).
