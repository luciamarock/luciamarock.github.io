validation.validation_engine module

This module contains the implementation of all the validators

Created on Tue Mar 21 09:31:30 2023

The create function is responsible for instantiating (and returning) the validator objects.

The creation is generally done once when “loading” the recipes; in fact the “create” method is called by SmartControllers.controllers_interface.load_recipes

@author: luciamarock

class validation.validation_engine.TPG_validator(filename)[source]

Bases: object

Recipe validator class

The TPG_validator object is tipically used when loading the recipes from files (.json), this happens at workflow startup (for example).

It receives the “filename” as initialization parameter; it is the full path to the “rules” file to load which is an .ini file named after the validator itself.

The TPG_validator (as well as the other validator classes) is instantiated by the “create” function of this module.

validate(instance, PVs, filename)[source]

This method is responsible for validating the TPG instances

it bases upon the reules file (which is an .ini file named after this validator).

Parameters:

  • instance – The (Smart Controller) instance (as retrieved from controller_interface.registered_instances)

  • PVs – The dictionary of parameters, as retrieved from the .json file (recipes) at workflow startup.

  • filename – the .json file name found in the recipes folder (and sub-folders)

The method tries to find the current “instance.attribute” among the “options” of the .ini file containing the rules, then it tries to evaluate the expression for that attribute, if the evaluation is successfully completed it means that the parameter has passed the validation phase.

Next it searches for a key for storing the set of parameters inside the Controller’s Instance, in case, it appends the errors.

Returns:

the errors list (empty if no error occurred)
