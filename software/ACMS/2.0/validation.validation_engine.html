validation.validation_engine module

Validation Engine Module for ACMS Recipe & Worker Configurations.

This module provides concrete implementations of validation classes used to verify recipe parameters, Smart Controller instance attributes, and worker execution rules.

Validation logic relies on external rule definitions formatted as either INI configuration files (parsed via configparser.ConfigParser) or XML schema files (parsed via xml.etree.ElementTree).

Module Dependencies:

  • utilities.tool_internals: XML-to-dictionary translation utilities.

  • utilities.util_functions: Access to system environment settings.

  • configparser: INI rule configuration parser.

  • xml.etree.ElementTree: XML schema rule parser.

The TPG_validator object is typically instantiated during workflow startup when loading JSON recipe files. It reads rule expressions from an INI configuration file named after the target validator class.

validate(instance, PVs, filename)[source]

Validate a TPG Smart Controller instance against loaded INI rules.

Extracts target attributes from the controller instance and evaluates the rule expressions defined in the [attributes] section of the INI file. Furthermore, it maps and registers recipe parameters to the target controller instance if a matching recipe key exists in the [recipes] section.

Parameters:

  • instance (object) – The Smart Controller instance registered in the runtime catalog.

  • PVs (dict) – Dictionary of Process Variables and parameters loaded from a JSON recipe.

  • filename (str) – Base filename of the target JSON recipe (without extension).

Returns:

List of string error messages encountered during attribute evaluation or recipe key mapping. Returns an empty list if validation passes entirely.

Return type:

list of str

class validation.validation_engine.worker_validator(parameters_dict, interlocks, instance_name)[source]

Bases: object

Validator class for worker process parameters and safety interlocks.

Loads rule specifications from an XML schema file located in the application’s resources directory (<resources_directory>/rules/<instance_name>_rules.xml) to verify type constraints, range limits (min/max), and structural validity of interlock definitions.

Parameters:

  • parameters_dict (dict) – Operational parameters configured for the worker instance.

  • interlocks (dict) – Dictionary of defined interlocks, rearm flags, and error codes.

  • instance_name (str) – Unique identifier name of the target worker instance.
