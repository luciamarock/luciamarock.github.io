workflows_interface module

Interface module for the Workflows.

This module constitutes the operational starting point of the Recipe Management System and ACMS execution framework. It is invoked directly by main_program.py after the hardware configuration and discovery phase (“knowledge acquisition”) has finished loading the physical Smart Controller definitions from system resource XML files.

The interface is responsible for:

  1. Validating recipe folder structures and subsystem integrity.

  2. Registering and starting background background workflow processing threads.

  3. Dispatching execution to the requested User Interface / Operation Mode:

    • API Mode: Boots the ACMS background API client and execution runner to interact with the LIPAc Campaign Manager (LCM) via polling (GET /api/v0.5/automation/jobs/next), event batching (POST /api/v0.5/automation/jobs/{job_id}/events), and 2-second heartbeats.

    • GUI Mode: Launches the PyQt5 graphical interface for local operator control.

    • CLI Mode: Provides an interactive command-line loop for debugging, manual workflow querying, and safe process spawning of tools like the Template Editor.

Module Dependencies:

  • utilities.util_functions: Global workspace configuration and settings state.

  • controllersInterface: Type and instance registration for EPICS controllers.

  • editor_interface: Archive scanning and template editor operations.

  • gui_process_launcher: Isolated process launcher for external PySide/PyQt tools.

  • API.runner: Entry point for launching the ACMS-LCM communication loop.

@author: luciamarock

workflows_interface.init()[source]

Initialize workspace recipe directories and validate subsystem controller integrity.

This function performs structural pre-flight checks before workflows can be safely executed:

  • Verifies the existence of the base recipes/ directory in the workspace, creating it if missing.

  • Ensures all registered controller types belong to a single, unified hardware subsystem.

  • Checks that every controller instance declared inside a controller type actually exists within the registered instances dictionary, creating instance sub-folders as needed.

  • Establishes network/EPICS connectivity if an AutoConditioningWorkflow instance is registered.

Returns:

True if initialization and connectivity checks succeeded, enabling main_program to invoke start(); False otherwise.

Return type:

bool

workflows_interface.start()[source]

Start workflow worker threads and launch the selected operating mode.

The execution flow progresses as follows:

  1. Invokes CI.create_validators() to build runtime validators across all controllers.

  2. Configures general settings and spawns dedicated background daemon threads for every registered workflow (e.g., automatic workflow, sentinel workers, phase alignment).

  3. Evaluates UF.settings["UI"] to branch into the designated interface loop:

    • API Mode: Imports and launches the ACMS API Runner service (API.runner.start_api_server()), connecting ACMS to the LIPAc Campaign Manager (LCM) backend endpoints over HTTP. Blocks on a 1-second keep-alive loop until interrupted.

    • GUI Mode: Initializes a PyQt5.QtWidgets.QApplication instance and displays the main desktop application window.

    • CLI Mode: Enters a terminal loop processing interactive commands (status, editor, help, exit) and gracefully stops registered workflows upon termination.

Raises:

KeyboardInterrupt – Trapped during API or CLI modes to safely halt registered workflow threads and release hardware/EPICS resources prior to process shutdown.
