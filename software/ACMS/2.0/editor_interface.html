editor_interface module

Template Editor Network Profiler and PV Discovery Interface.

This module provides the backend discovery, extraction, and Channel Access (CA) sweeping capabilities required by the ACMS Template Editor sub-application.

In the Recipe Management System (RMS) inherited by ACMS, recipes are dynamically generated from high-level operational templates. To assist operators in editing and authoring these templates, this module profiles EPICS Process Variables (PVs) by:

  1. Extracting candidate PV lists from archive PostgreSQL databases or Display Builder (Phoebus .bob) HMI files.

  2. Executing concurrent multi-threaded EPICS CA network sweeps using a shared CA context loop.

  3. Collecting requested PV fields (e.g., limits, units, current values).

  4. Sanitizing telemetry payloads by converting IEEE floating-point NaN values into JSON-compliant null literals to prevent serialization crashes.

  5. Formatting and delivering structured PV metadata dictionaries to the Template Editor GUI.

Module Dependencies:

  • epics: PyEPICS Channel Access interface and thread context management.

  • utilities.bob_parser: Utility for parsing Phoebus .bob XML screens.

  • utilities.db_query: Query helper for fetching archived PV lists from SQL.

editor_interface.load_configuration(config_path)[source]

Load runtime parameters and configuration fields from a JSON resource file.

Parameters:

config_path (str or Path) – File path to the JSON configuration file containing Channel Access settings, field specifications, and HMI display paths.

Returns:

A 4-element tuple containing:

  • CA_TIMEOUT (float): Network connection timeout in seconds per PV.

  • CA_PARALLELISM (int): Maximum number of concurrent CA worker threads per batch.

  • PV_FIELDS (list of str): List of EPICS PV attributes to retrieve.

  • HMI_FILES (dict): Dictionary mapping display key identifiers to target .bob file paths.

Return type:

tuple

Raises:

SystemExit – If the configuration file is missing, contains invalid JSON syntax, or lacks required keys.

editor_interface.run_network_sweep(pv_names, parallelism, fields_to_get, timeout)[source]

Orchestrate concurrent thread batches to profile online EPICS PV channels.

Initializes the C-level libca library context and spawns batch groups of epics.ca.CAThread threads bounded by the parallelism limit to safely query the control network without overwhelming local socket descriptors.

Parameters:

  • pv_names (list of str) – List of PV names to profile over Channel Access.

  • parallelism (int) – Number of concurrent worker threads allowed per execution batch.

  • fields_to_get (list of str) – PV attributes to fetch from connected channels.

  • timeout (float) – Channel connection timeout in seconds per PV.

Returns:

A dictionary mapping PV names to attribute dicts (or None if unreachable).

Return type:

dict

editor_interface.san_bob_file(resources_dir, key)[source]

Extract PVs referenced inside a specific Phoebus Display (.bob) file and profile them.

Used when an operator requests template editing for a specific sub-system HMI display. It parses the targeted .bob XML screen file, extracts all embedded PV identifiers, and profiles their live EPICS network states.

Parameters:

  • resources_dir (str) – Base path to the application’s resources directory containing config.json.

  • key (str) – Lookup key in HMI_FILES corresponding to the target .bob display file.

Returns:

A sanitized dictionary of PVs extracted from the display file along with their live field metadata.

Return type:

dict

Raises:

SystemExit – If the target .bob display file cannot be located or parsed.

editor_interface.sanitize_data(pv_map)[source]

Sanitize scanned telemetry metadata by converting float NaN values to JSON nulls.

EPICS floating-point PVs returning NaN (Not a Number) cause serialization errors when converting dictionaries into standard JSON strings. This function replaces all NaN float values with None (which maps to JSON null).

Parameters:

pv_map (dict) – The raw PV metadata dictionary produced by run_network_sweep().

Returns:

The sanitized PV dictionary suitable for JSON serialization and GUI consumption.

Return type:

dict

editor_interface.save_manifest(pv_map, output_path)[source]

Write the sanitized PV metadata dictionary to a JSON file on disk.

Creates parent directories if missing and formats the JSON output with 4-space indentation and sorted keys.

Parameters:

  • pv_map (dict) – Sanitized dictionary mapping PV names to field values.

  • output_path (Path or str) – Target file destination path.

editor_interface.scan_archive_network(resources_dir)[source]

Fetch all archived PVs from the SQL database and profile their live network status.

This function serves as the primary data payload builder when launching the Template Editor from the main ACMS CLI or GUI interface. It:

  1. Loads system settings from config.json.

  2. Retrieves the complete list of target PVs from the archive SQL database.

  3. Executes a live Channel Access network sweep.

  4. Sanitizes field data and returns the completed payload dictionary.

Parameters:

resources_dir (str) – Base path to the application’s resources directory containing config.json.

Returns:

A sanitized map of all archived PV names and their live EPICS field attributes.

Return type:

dict

Raises:

SystemExit – If database connection or querying fails critically.

editor_interface.scan_pv_worker(name, results_dict, fields_to_get, timeout)[source]

Worker thread target to extract EPICS metadata safely via a shared CA context.

Attaches the executing thread to the global C library CA context (MAIN_CONTEXT), attempts connection to the specified PV, reads requested attributes, and populates the shared results dictionary.

Parameters:

  • name (str) – The EPICS Process Variable name to connect to.

  • results_dict (dict) – Shared dictionary where scanned PV metadata is recorded.

  • fields_to_get (list of str) – List of PV attributes/fields to query.

  • timeout (float) – Connection timeout threshold in seconds.
